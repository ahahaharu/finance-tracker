# Контракт REST API

**Проект:** finance-tracker
**Базовый путь:** `/api/v1`
**Версия документа:** 1.0

Документ фиксирует форматы запросов и ответов до начала разработки.
Ссылки вида FR-x.y указывают на требования из `docs/spec.md`.

---

## 1. Общие правила

| Правило | Значение |
|---|---|
| Формат | `application/json; charset=utf-8` |
| Аутентификация | сессионный cookie, выдаётся Auth.js (FR-11.2) |
| Даты в запросах и ответах | ISO 8601, UTC, с суффиксом `Z` |
| Даты без времени | `YYYY-MM-DD` |
| Денежные суммы | целое число минорных единиц |
| Именование полей | `camelCase` |
| Идентификаторы | строка (cuid) |

Все обработчики маршрутов остаются тонкими: разбор запроса, проверка схемой,
получение сессии, вызов сервиса, преобразование ошибки в ответ (NFR-4.1).
Бизнес-логика в них отсутствует.

Серверные действия интерфейса вызывают **те же самые сервисы**, а не эти
конечные точки. HTTP-слой существует для внешних клиентов и для демонстрации
требования FR-11.1, а не как посредник между интерфейсом и базой данных.

---

## 2. Формат ответа

### 2.1. Одиночный ресурс

```json
{
  "id": "clx7f2k...",
  "name": "Основная карта",
  "type": "CARD",
  "currency": "BYN",
  "initialBalance": 15000,
  "currentBalance": 42350,
  "createdAt": "2026-03-01T10:12:00Z"
}
```

### 2.2. Коллекция

```json
{
  "data": [ { "id": "..." } ],
  "meta": {
    "page": 1,
    "pageSize": 50,
    "total": 327,
    "totalPages": 7
  }
}
```

Коллекции всегда возвращаются в такой оболочке, даже когда постраничный вывод
для них не имеет смысла. Единообразие важнее краткости: клиент разбирает
любой список одним и тем же кодом.

### 2.3. Ошибка

```json
{
  "error": {
    "code": "CATEGORY_HAS_TRANSACTIONS",
    "message": "Category has related transactions",
    "details": { "transactionCount": 340 }
  }
}
```

Поле `message` предназначено для журналов и отладки и всегда на английском.
Текст для пользователя формирует клиент по значению `code` и текущей локали
(FR-11.5). Поле `details` необязательно и содержит данные для подстановки
в сообщение.

---

## 3. Коды состояния

| Код | Когда возвращается |
|---|---|
| 200 | успешное чтение, изменение или удаление |
| 201 | ресурс создан; заголовок `Location` содержит путь к нему |
| 400 | запрос синтаксически некорректен, неразбираемый JSON |
| 401 | сессия отсутствует или истекла |
| 403 | сессия есть, но прав на ресурс или действие нет |
| 404 | ресурс не существует либо принадлежит другому пользователю |
| 409 | конфликт состояния: нарушена уникальность, ресурс связан с другими |
| 422 | данные разобраны, но не прошли проверку схемой |
| 429 | превышена частота запросов (NFR-1.5) |

Про 404 против 403: обращение к чужому ресурсу возвращает **404, а не 403**.
Ответ 403 подтверждал бы существование объекта с таким идентификатором, что
само по себе является утечкой информации.

---

## 4. Коды ошибок

| Код | HTTP | Значение |
|---|:--:|---|
| `VALIDATION_FAILED` | 422 | данные не прошли проверку; `details` содержит список полей |
| `UNAUTHENTICATED` | 401 | сессия отсутствует |
| `FORBIDDEN` | 403 | недостаточно прав для действия |
| `NOT_FOUND` | 404 | ресурс не найден |
| `EMAIL_TAKEN` | 409 | адрес уже зарегистрирован |
| `WALLET_NAME_TAKEN` | 409 | счёт с таким наименованием уже есть |
| `CATEGORY_NAME_TAKEN` | 409 | категория с таким наименованием и видом уже есть |
| `WALLET_HAS_TRANSACTIONS` | 409 | счёт нельзя удалить (FR-2.4) |
| `CATEGORY_HAS_TRANSACTIONS` | 409 | категорию нельзя удалить (FR-3.4) |
| `BUDGET_EXISTS` | 409 | бюджет по этой категории на этот месяц уже задан |
| `CATEGORY_KIND_MISMATCH` | 422 | вид категории не соответствует типу операции (FR-4.5) |
| `FUTURE_DATE` | 422 | дата операции в будущем (FR-4.4) |
| `SAME_WALLET_TRANSFER` | 422 | счёт-источник совпадает с получателем (FR-5.5) |
| `RATE_NOT_AVAILABLE` | 422 | нет курса на дату операции и ранее (FR-7.5) |
| `ACCOUNT_BLOCKED` | 403 | учётная запись заблокирована (FR-1.8) |
| `INVALID_CREDENTIALS` | 401 | неверная пара адрес — пароль |
| `SELF_MODIFICATION_FORBIDDEN` | 403 | администратор изменяет собственную запись (FR-10.4) |
| `RATE_LIMITED` | 429 | превышена частота запросов |
| `INTERNAL_ERROR` | 500 | непредвиденная ошибка |

Формат `details` для `VALIDATION_FAILED`:

```json
{
  "details": {
    "fields": [
      { "path": "amount", "code": "too_small" },
      { "path": "occurredAt", "code": "invalid_date" }
    ]
  }
}
```

## 5. Параметры коллекций

Единые для всех списков (FR-11.6).

| Параметр | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `page` | integer ≥ 1 | 1 | |
| `pageSize` | integer 1…100 | 50 | FR-9.3 |
| `sort` | string | зависит от ресурса | формат `поле:asc` либо `поле:desc` |

Неизвестный параметр запроса игнорируется. Некорректное значение известного
параметра возвращает `VALIDATION_FAILED`.

## 6. Конечные точки

### 6.1. Учётная запись

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/auth/register` | регистрация (FR-1.1) |
| `GET` | `/api/v1/me` | профиль текущего пользователя |
| `PATCH` | `/api/v1/me` | изменение имени, языка интерфейса и валюты отчётности |
| `POST` | `/api/v1/me/password` | смена пароля (FR-1.7) |

Вход и выход обслуживаются Auth.js по путям `/api/auth/*` и в настоящий
контракт не входят.

Валюта отчётности задаётся при регистрации и изменяется в профиле
(FR-1.6, FR-7.2). Смена валюты запускает пересчёт: у каждой операции
пользователя `rate` и `baseAmount` пересчитываются по курсу её собственной
`rateDate`, у каждого бюджета `limitAmount` и `currency` — по курсу первого
числа его месяца (FR-7.7). Пересчёт выполняется одной транзакцией: если
курса на какую-то из требуемых дат нет вовсе, валюта не меняется и запрос
отклоняется кодом `RATE_NOT_AVAILABLE`.

Пересчёт по курсам соответствующих дат, а не по текущему, — прямое следствие
FR-7.6: мартовский расход остаётся мартовским, месячные итоги задним числом
не плывут.

`POST /auth/register`

```json
{
  "email": "user@example.com",
  "password": "correct-horse-8",
  "name": "Андрей",
  "baseCurrency": "BYN"
}
```

Ответ `201`: объект пользователя без поля `passwordHash`.
Ошибки: `EMAIL_TAKEN`, `VALIDATION_FAILED`, `RATE_LIMITED`.

### 6.2. Счета

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/wallets` | список с текущими остатками (FR-2.6) |
| `POST` | `/api/v1/wallets` | создание |
| `GET` | `/api/v1/wallets/{id}` | один счёт |
| `PATCH` | `/api/v1/wallets/{id}` | изменение наименования, типа, начального остатка |
| `DELETE` | `/api/v1/wallets/{id}` | удаление |

Элемент списка содержит `currentBalance` в валюте счёта и `baseBalance`
в валюте отчётности.

`currentBalance` — начальный остаток плюс операции по счёту, вычисляется
агрегатом и нигде не хранится (FR-2.5). `baseBalance` — тот же остаток,
конвертированный по курсу на текущую дату; это **не** сумма `baseAmount`
операций. То же правило действует для общего остатка по всем счетам
(FR-8.1). Обоснование — `docs/data-model.md`, §5.8.

Список упорядочен по наименованию; параметр `sort` к этому ресурсу
не применяется. `PATCH` принимает любое подмножество полей `name`, `type`
и `initialBalance`; `currency` в теле запроса отбрасывается (FR-2.2).

Ошибки: `WALLET_NAME_TAKEN`, `WALLET_HAS_TRANSACTIONS`, `NOT_FOUND`.

### 6.3. Категории

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/categories` | список; фильтр `kind=INCOME\|EXPENSE` |
| `POST` | `/api/v1/categories` | создание |
| `GET` | `/api/v1/categories/{id}` | одна категория |
| `PATCH` | `/api/v1/categories/{id}` | изменение наименования и цвета |
| `DELETE` | `/api/v1/categories/{id}` | удаление |

Список упорядочен по виду, затем по наименованию; параметр `sort` к этому
ресурсу не применяется. `PATCH` принимает любое подмножество полей `name`
и `color`; `kind` в теле запроса отбрасывается (FR-3.3). Цвет принимается
только из фиксированного набора двенадцати оттенков `--cat-1..12`
(`docs/design-system.md`, раздел 2); произвольное значение отклоняется
кодом `VALIDATION_FAILED`.

Ошибки: `CATEGORY_NAME_TAKEN`, `CATEGORY_HAS_TRANSACTIONS`, `NOT_FOUND`.

### 6.4. Операции

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/transactions` | список с фильтрами (FR-9.1) |
| `POST` | `/api/v1/transactions` | создание |
| `GET` | `/api/v1/transactions/{id}` | одна операция |
| `PATCH` | `/api/v1/transactions/{id}` | изменение |
| `DELETE` | `/api/v1/transactions/{id}` | удаление |
| `GET` | `/api/v1/transactions/export` | выгрузка в CSV (FR-9.7) |

Параметры фильтрации:

| Параметр | Формат | Примечание |
|---|---|---|
| `from`, `to` | `YYYY-MM-DD` | период по дате операции |
| `walletId` | id | допускается повторение параметра |
| `categoryId` | id | допускается повторение параметра |
| `type` | `INCOME`, `EXPENSE`, `TRANSFER` | `TRANSFER` покрывает оба направления |
| `q` | строка | поиск по комментарию (FR-9.2) |
| `sort` | `occurredAt:desc` | по умолчанию |

Блок `meta` в этом ресурсе дополняется итогами по текущему набору фильтров
(FR-9.6):

```json
"meta": {
  "page": 1, "pageSize": 50, "total": 327, "totalPages": 7,
  "totals": { "income": 480000, "expense": 312450, "net": 167550,
              "currency": "BYN" }
}
```

Итоги считаются в валюте отчётности и не включают переводы (FR-8.6).

`POST /api/v1/transactions`

```json
{
  "type": "EXPENSE",
  "amount": 2450,
  "walletId": "clx7f2k...",
  "categoryId": "clx8a1p...",
  "occurredAt": "2026-08-09T14:30:00Z",
  "note": "Продукты на неделю"
}
```

Ответ `201`: объект операции с рассчитанными `baseAmount`, `rate`, `rateDate`.
Ошибки: `CATEGORY_KIND_MISMATCH`, `FUTURE_DATE`, `RATE_NOT_AVAILABLE`,
`VALIDATION_FAILED`, `NOT_FOUND`.

`GET /api/v1/transactions/export` принимает те же фильтры, отдаёт
`text/csv; charset=utf-8` с заголовком `Content-Disposition: attachment`.
Постраничный вывод к выгрузке не применяется.

### 6.5. Переводы

| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/api/v1/transfers` | создание перевода |
| `DELETE` | `/api/v1/transfers/{groupId}` | удаление обеих записей (FR-5.7) |

```json
{
  "fromWalletId": "clx7f2k...",
  "toWalletId": "clx9d4m...",
  "amountFrom": 10000,
  "amountTo": 32500,
  "occurredAt": "2026-08-09T14:30:00Z",
  "note": "Перевод на накопительный"
}
```

При совпадении валют счетов `amountTo` не передаётся и приравнивается
к `amountFrom` (FR-5.3). При различии валют оба поля обязательны, фактический
курс операции вычисляется как их отношение (FR-5.4).

Ответ `201`: объект с `transferGroupId` и обеими созданными записями.
Ошибки: `SAME_WALLET_TRANSFER`, `VALIDATION_FAILED`, `NOT_FOUND`.

Изменение перевода отдельным методом не предусмотрено: правка выполняется
удалением и созданием заново (FR-5.8).

### 6.6. Бюджеты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/budgets` | список за месяц; параметр `month=YYYY-MM` |
| `POST` | `/api/v1/budgets` | создание |
| `PATCH` | `/api/v1/budgets/{id}` | изменение суммы лимита |
| `DELETE` | `/api/v1/budgets/{id}` | удаление |

Элемент списка содержит исполнение (FR-6.4):

```json
{
  "id": "clxb2n...",
  "categoryId": "clx8a1p...",
  "month": "2026-08-01",
  "limitAmount": 40000,
  "spentAmount": 31240,
  "remainingAmount": 8760,
  "usedPercent": 78.1,
  "isExceeded": false,
  "currency": "BYN"
}
```

Ошибки: `BUDGET_EXISTS`, `CATEGORY_KIND_MISMATCH`, `NOT_FOUND`.

### 6.7. Аналитика

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/analytics/summary` | доход, расход, сальдо, общий остаток (FR-8.1, FR-8.2) |
| `GET` | `/api/v1/analytics/by-category` | распределение расходов по категориям (FR-8.3) |
| `GET` | `/api/v1/analytics/monthly` | динамика за 6 месяцев (FR-8.4) |

Все три принимают `from` и `to`; для `monthly` период игнорируется.
Все суммы — в валюте отчётности. Переводы исключены.

### 6.8. Курсы валют

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/rates` | курсы на дату; параметр `date=YYYY-MM-DD` |

Обновление курсов выполняется по расписанию платформы и вручную через
раздел администрирования.

### 6.9. Администрирование

Доступно только роли `ADMIN`. Проверка роли выполняется в сервисном слое
(NFR-1.2), а не только в промежуточном слое маршрутизации.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/admin/users` | список учётных записей (FR-10.1) |
| `PATCH` | `/api/v1/admin/users/{id}` | блокировка, разблокировка, смена роли |
| `GET` | `/api/v1/admin/stats` | агрегированная статистика (FR-10.5) |
| `POST` | `/api/v1/admin/rates/refresh` | принудительное обновление курсов (FR-10.6) |

Элемент списка содержит адрес, имя, роль, дату регистрации, статус
и количество операций. **Суммы, счета, категории и бюджеты пользователей
не возвращаются** (FR-10.7).

Ошибки: `FORBIDDEN`, `SELF_MODIFICATION_FORBIDDEN`, `NOT_FOUND`.

### 6.10. Спецификация

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/openapi.json` | спецификация OpenAPI 3.1 |
| `GET` | `/api-docs` | интерфейс просмотра спецификации (FR-11.7) |

Спецификация формируется из тех же схем Zod, которыми проверяются запросы, —
через `zod-to-openapi`. Ручная синхронизация документации с кодом исключена.

## 7. Ограничение частоты

| Путь | Ограничение |
|---|---|
| `/api/v1/auth/register` | 10 запросов за 15 минут с адреса |
| `/api/auth/callback/credentials` | 10 запросов за 15 минут с адреса |
| остальные | не ограничены |

Превышение возвращает `429` с кодом `RATE_LIMITED` и заголовком `Retry-After`.

---

## 8. Что в контракт не входит

| Функция | Причина |
|---|---|
| Восстановление пароля | вне области реализации (`docs/spec.md`, раздел 8) |
| Токены для внешних клиентов | аутентификация только сессионным cookie |
| Массовые операции | не требуется сценариями |
| Версия API выше `v1` | одна версия на весь срок работы |
